# componentmanger.js

## Общее описание

Файл `componentmanger.js` является частью ядра SCWeb и реализует менеджер компонентов. Этот файл отвечает за регистрацию, инициализацию и создание экземпляров компонентов визуализации различных форматов и внешних языков.

## Основные компоненты

### 1. SCWeb.core.ComponentType

Перечисление типов компонентов:

- `viewer` (0) - компонент просмотра
- `editor` (1) - компонент редактирования

### 2. SCWeb.core.ComponentManager

Основной объект менеджера компонентов, содержащий все методы для работы с компонентами.

#### Свойства объекта:

- `_listener` - объект для прослушивания событий регистрации/удаления компонентов
- `_initialize_queue` - очередь инициализации компонентов
- `_componentCount` - количество ожидающих инициализации компонентов
- `_factories_fmt` - словарь фабрик компонентов по форматам
- `_factories_ext_lang` - словарь фабрик компонентов по внешним языкам
- `_ext_langs` - словарь форматов по внешним языкам
- `_keynodes` - массив ключевых узлов, запрошенных компонентами

#### Методы объекта:

##### Методы инициализации:

**`init()`** - асинхронный метод инициализации менеджера компонентов. Выполняет:
1. Сбор всех ключевых узлов из очереди инициализации
2. Разрешение sc-addr для всех ключевых узлов через сервер
3. Регистрацию фабрик компонентов для разрешённых форматов
4. Возвращает Promise, который разрешается после завершения инициализации

##### Методы регистрации:

**`appendComponentInitialize(component_def)`** - добавляет функцию инициализации компонента в очередь

Параметры `component_def`:
- `formats` - массив системных идентификаторов поддерживаемых форматов
- `factory` - фабричная функция компонента
- `ext_lang` - внешний язык (опционально)
- `struct_support` - поддержка структур (опционально)
- `getRequestKeynodes` - функция для получения дополнительных ключевых узлов (опционально)

**`registerFactory(format_addr, func)`** - регистрирует фабрику компонента для указанного формата

Параметры:
- `format_addr` - sc-addr формата
- `func` - фабричная функция компонента

##### Методы проверки:

**`isStructSupported(format_addr)`** - проверяет, поддерживает ли компонент указанного формата структуры

Параметры:
- `format_addr` - sc-addr формата

Возвращает:
- `true` если компонент поддерживает структуры
- Выбрасывает исключение если компонент не найден

##### Методы создания окон:

**`createWindowSandboxByFormat(options)`** - асинхронный метод создания окна компонента по формату

Параметры `options`:
- `format_addr` - sc-addr формата окна
- `addr` - sc-addr просматриваемого/редактируемого элемента
- `is_struct` - флаг, указывающий является ли элемент структурой
- `container` - ID DOM-контейнера
- `window_id` - ID окна
- `canEdit` - флаг запроса редактора
- `content` - содержимое
- `contentStyle` - стиль содержимого
- `command_state` - состояние команды

Возвращает Promise, который разрешается при успешном создании

**`createWindowSandboxByExtLang(options, callback)`** - создаёт окно компонента по внешнему языку

Параметры `options`:
- `ext_lang_addr` - sc-addr внешнего языка
- `addr` - sc-addr просматриваемого/редактируемого элемента
- `is_struct` - флаг структуры
- `container` - ID контейнера
- `canEdit` - флаг редактирования
- `command_state` - состояние команды

Возвращает:
- Экземпляр sandbox созданного окна
- `null` если создание не удалось

##### Методы запроса информации:

**`getPrimaryFormatForExtLang(ext_lang_addr)`** - возвращает primary sc-addr формата для указанного внешнего языка

Параметры:
- `ext_lang_addr` - sc-addr внешнего языка

Возвращает:
- sc-addr первого формата или `null`

**`getScStructSupportExtLangs()`** - возвращает список внешних языков с поддержкой визуализации sc-структур

Возвращает:
- Массив sc-addr внешних языков

##### Методы для событий:

**`setListener(listener)`** - устанавливает слушатель событий компонентов

Параметры `listener`:
- `componentRegistered(compDescr)` - функция вызываемая при регистрации компонента
- `componentUnregistered(compDescr)` - функция вызываемая при удалении компонента

**`_fireComponentRegistered(compDescr)`** - внутренний метод генерации события регистрации компонента

**`_fireComponentUnregistered(compDescr)`** - внутренний метод генерации события удаления компонента

## Процесс инициализации

1. Компоненты добавляются в очередь инициализации через `appendComponentInitialize`
2. При вызове `init()`:
   - Собираются все ключевые узлы из очереди
   - С помощью `SCWeb.core.Server.resolveScAddr` разрешаются их sc-addr
   - Для каждого компонента регистрируются фабрики для каждого формата
   - Создаётся соответствие между внешними языками и форматами
3. После инициализации компоненты готовы к созданию окон

## Процесс создания окна компонента

1. При запросе окна ищется зарегистрированная фабрика компонента:
   - По формату через `createWindowSandboxByFormat`
   - По внешнему языку через `createWindowSandboxByExtLang`
2. Создаётся экземпляр `ComponentSandbox` с переданными параметрами
3. Вызывается фабричная функция компонента с переданным sandbox
4. При успехе компонент создаёт визуализацию в контейнере

## Взаимодействие с другими модулями

- `SCWeb.core.ComponentSandbox` - создаёт экземпляры sandbox для компонентов
- `SCWeb.core.Server` - используется для разрешения sc-addr ключевых узлов
- `SCWeb.ui.KeyboardHandler` - подписывает обработчики клавиатуры для редакторов
- `SCWeb.ui.OpenComponentHandler` - подписывает обработчики открытия компонентов
